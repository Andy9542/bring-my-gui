# bring-my-gui

[![stack](https://github.com/Andy9542/bring-my-gui/actions/workflows/stack.yml/badge.svg)](https://github.com/Andy9542/bring-my-gui/actions/workflows/stack.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English](README.md) | **Русский**

Запустить GUI-приложение внутри headless Linux-контейнера и увидеть его окно на
своём экране. Образу не нужен ни X-сервер, ни десктоп, ни переделка: стек
(**Xvfb + openbox + x11vnc**) ставится в тот контейнер, который у вас уже есть,
а на вашей стороне нужен только VNC-клиент — в macOS и в большинстве
Linux-десктопов он встроенный.

![Firefox внутри контейнера fedora:41, вид с хоста](docs/hero.png)

*Firefox внутри `fedora:41` — в образе нет X-сервера вообще. Справа — шелл в том
же контейнере, который это доказывает. На хосте не установлено ничего, кроме
VNC-клиента. Страница в браузере — демонстрационная, поэтому кадр сам подписывает
свои детали.*

## Два способа использовать

**Как skill для агента** — то, для чего это и сделано. Агент живёт в контейнере
или песочнице, вы просите показать GUI, и он делает всё сам: ставит стек,
подбирает разрешение под *ваш* экран, запускает приложение с нужными флагами
тулкита, отдаёт строку подключения под вашу ОС и уже знает, что делать, когда
картинка мерцает, буфер обмена работает в одну сторону или начинают пропадать
русские буквы.

**Как набор bash-скриптов** — если агент не при чём и просто нужен GUI из
контейнера.

## Попробовать на одном контейнере

```bash
git clone https://github.com/Andy9542/bring-my-gui.git
cd bring-my-gui

# контейнер без X-сервера, VNC-порт опубликован на вашу машину
docker run -d --name gui-demo -p 5900:5900 \
  -v "$PWD/skills/bring-my-gui:/opt/bmg:ro" fedora:41 sleep infinity

docker exec gui-demo bash -c '
  bash /opt/bmg/scripts/setup.sh &&
  RES=1440x900 VNC_PASS=demo bash /opt/bmg/scripts/gui-stack.sh start &&
  dnf install -y -q /usr/bin/xclock &&
  nohup env DISPLAY=:0 xclock -digital -update 1 >/dev/null 2>&1 &'
```

Подключаемся со своей машины, пароль `demo`:

| ОС хоста | Подключение |
|---|---|
| macOS | `open vnc://localhost:5900` (встроенный Screen Sharing) или Finder → ⌘K |
| Windows | [TightVNC Viewer](https://www.tightvnc.com/download.php) или TigerVNC → `localhost:5900` |
| Linux | `vncviewer localhost:5900` или Remmina |

Вставка внутри сессии — **Ctrl+V**: сессия линуксовая, ⌘V с макбука до неё не
доходит. Закончили: `docker rm -f gui-demo`.

Так это выглядит с другой стороны — та же сессия, снятая на маке во встроенном
Screen Sharing. В заголовке окна — имя хоста контейнера и номер дисплея, а справа
внутри контейнера работает `gui-stack.sh status`:

![Дисплей контейнера в macOS Screen Sharing](docs/host.png)

## Поставить как skill

```bash
# Cursor — как плагин (манифест в репозитории)
git clone https://github.com/Andy9542/bring-my-gui.git ~/.cursor/plugins/local/bring-my-gui

# Cursor — только skill
cp -r skills/bring-my-gui ~/.cursor/skills/

# Claude Code
cp -r skills/bring-my-gui ~/.claude/skills/
```

Любой другой агент: дайте ему
[`skills/bring-my-gui/SKILL.md`](skills/bring-my-gui/SKILL.md) и попросите GUI.
Формулировка вида «покажи приложение из песочницы у меня на экране, у меня
14-дюймовый MacBook» работает лучше всего — размер экрана определяет разрешение
и масштаб.

## Вход в аккаунт приложения внутри контейнера

Агент живёт внутри контейнера. Браузера нет. Десктопные приложения (Cursor,
Electron) всё равно пытаются его запустить — ради этого и существует мост.
Подмена отвечает вместо `xdg-open` / `x-www-browser` / `$BROWSER`, в том числе
когда приложение зовёт `/usr/bin/xdg-open` по абсолютному пути. Агент делает
`watch` и кладёт ссылку в чат; вход вы заканчиваете у себя на хосте.

```bash
docker exec gui-demo bash /opt/bmg/scripts/oauth-bridge.sh install
docker exec gui-demo bash /opt/bmg/scripts/oauth-bridge.sh watch   # напечатает ссылку
```

Cursor сам забирает токен, как только вы подтверждаете. Claude Code печатает
ссылку для вставки кода (и может ещё стучаться на случайный localhost-порт,
который изнутри не пробросить) — открываете напечатанную ссылку, код
возвращаете в TUI. Подробности:
[SKILL.md § Browser login](skills/bring-my-gui/SKILL.md).

## Что skill знает, а свежий агент — нет

Каждый пункт ниже был выловлен живьём, стоил круга отладки, а теперь это одна
строка в skill:

- **x11vnc умирает сразу после старта** — образы песочниц экспортируют
  `WAYLAND_DISPLAY`, x11vnc считает сессию вейландовой и отказывается работать.
- **Русский ввод отваливается, по букве, со временем.** `setxkbmap us,ru`
  рассинхронизируется, `-add_keysyms` дрейфует и перезаписывает keycode'ы.
  Вместо этого стек заранее раскладывает весь алфавит на резервные keycode'ы —
  и диапазон keysym критичен: клиенты присылают `0x01000000|unicode`, поэтому
  `keycode N = 0x0435` создаёт другой, никем не найденный keysym, и «починка»
  только выглядит работающей.
- **Картинка непрерывно перерисовывается.** Проверка XDamage в x11vnc спотыкается
  на рендерерах в духе Electron и тихо переключается на опрос всего экрана.
  Флаг `-xdamage`, переданный дважды, оставляет damage включённым.
- **Ввод отмирает целиком**, а лог заливает *"waiting until all keys are up"* —
  потерянный key-release; лечится `-R clear_all`, а `-skip_keycodes 184`
  предотвращает macOS-вариант.
- **Мыло или микро-интерфейс.** Только разрешение экрана — всё мелкое, только
  масштаб приложения — текст мыльный. Нужно `RES` = 2× логического разрешения
  хоста *и* флаг масштаба тулкита.
- **Electron и Qt ставятся, но не стартуют** — недостающая `.so` из `ldd` ищется
  в репозитории *этого* дистрибутива, а не по имени пакета, запомненному в другом.
- **`pkill -f x11vnc` убивает ваш собственный шелл**, потому что шаблон есть и в
  его командной строке.
- **Подмена браузера устраивает форк-бомбу** — `xdg-open` в своей цепочке
  запасных вариантов зовёт `x-www-browser`, и подставная программа, отвечающая
  за оба имени, начинает вызывать саму себя, пока в контейнере не кончатся
  процессы. В мосте стоит защита по глубине, а при разборе завала важен
  порядок: сначала убрать подмену, потом убивать процессы.

Полный список симптомов и лечения:
[`references/gotchas.md`](skills/bring-my-gui/references/gotchas.md).

## Ставим по бинарю, а не по имени пакета

Стек — это набор программ: `Xvfb`, `x11vnc`, `openbox`, `setxkbmap`,
`xwininfo`. Имена пакетов у них разные в разных дистрибутивах, разъезжаются
между релизами и переименовываются. Поэтому `setup.sh` спрашивает у локального
индекса, какой пакет приносит `/usr/bin/<бинарь>`, и ставит его — один и тот же
скрипт работает на apt, dnf, yum и apk без зашитого списка.

## На чём проверено

CI прогоняет весь путь на каждый push и раз в неделю (пакеты в дистрибутивах
переименовывают — недельный прогон именно для этого). Каждая задача ставит стек
в чистый образ, поднимает дисплей, проверяет, что через опубликованный порт
приходит RFB-хендшейк, и выкладывает скриншот, снятый настоящим VNC-клиентом.
Это пригодилось сразу: первая версия workflow просила у Fedora пакет
`xorg-x11-apps` и не получала ничего, потому что в Fedora 41 `xclock` вынесли
в отдельный пакет. Теперь демо-приложение ставится по бинарнику, как и всё
остальное здесь.

| Образ | Холодная установка | Примечания |
|---|---|---|
| `ubuntu:24.04` | ~2.5 мин | один раз качается файловый индекс (`apt-file`), чтобы добрать последние бинари |
| `debian:bookworm-slim` | ~2.5 мин | то же |
| `fedora:41` | ~3.5 мин | `autocutsel` не собран в репозитории; буфер обмена с клиентом x11vnc всё равно синхронизирует |
| `alpine:3.21` | ~1.5 мин | в образе только `sh`, поэтому сначала `apk add bash` |

(Замеры при четырёх параллельных установках на ноутбуке; один контейнер
ставится быстрее.)

## Чего здесь нет

- **Звука.** VNC передаёт пиксели и ввод. Видео играет молча, и это не
  лечится флагами.
- **Интернета.** VNC — открытый протокол, а пароль это замок для удобства.
  Штатная схема: контейнер → опубликованный порт → та же машина. Если всё-таки
  нужно через сеть — только туннелем по SSH.
- **Wayland.** Приложение работает по X11 внутри контейнера — именно поэтому
  `WAYLAND_DISPLAY` снимается.
- **Готового образа с десктопом.** Ничего не подменяется: стек добавляется в
  тот контейнер, который уже запущен.

## Почему не X11-forwarding, xpra или образ с десктопом

- **Пробросить сокет X с хоста** (`-v /tmp/.X11-unix`) требует X-сервера на
  хосте: в macOS и Windows его нет, а в Linux это отдаёт контейнеру всю вашу
  X-сессию.
- **`xpra`** — протокол лучше для отдельных окон, но его надо ставить с двух
  сторон; здесь на стороне хоста VNC-клиент, который у вас уже есть.
- **Готовые образы «десктоп в контейнере»** хороши — если вы можете перейти на
  их образ. Здесь дисплей добавляется в тот образ, в котором уже работает агент.
- **noVNC / websockify** уместен, когда вместо VNC-клиента хочется браузер; он
  ставится поверх того же X-стека, который поднимает этот skill.

## Структура репозитория

```
skills/bring-my-gui/
  SKILL.md                 сам skill: решения, флаги, чеклисты
  references/gotchas.md    симптом → причина → лечение, всё выловлено живьём
  scripts/setup.sh         ставит стек по бинарям (apt/dnf/yum/apk)
  scripts/gui-stack.sh     start | stop | restart | status
  scripts/oauth-bridge.sh  вход в аккаунт без браузера: install | watch | listen
```
